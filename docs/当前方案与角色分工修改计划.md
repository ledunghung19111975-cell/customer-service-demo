# 智能客服：SOP 工作台与手机端演示方案

状态：本地原型设计与实现说明；实测范围见验收矩阵。

产出 Agent：Codex。主写、参与与最终收敛 Agent：Codex。

## 1. 目标与范围

客服工作台围绕“当前该做什么、已经做到哪一步、离线后由谁继续”组织接待。客户进线后由 AI 先接待；客服繁忙时，AI 可继续有限轮次的答复或信息采集。右侧 SOP 看板展示全部固定节点，根据客户诉求点亮相应步骤，并给出订单信息、可核对的预填内容和知识建议。

“手机端演示”Tab，用左侧手机聊天界面呈现客户咨询、人工服务和售后办理过程。右侧保持空白。

| 已明确的方向 | 方案落点 |
| --- | --- |
| 客服左侧继续保留“会话接待、工单处理” | 不新增一线一级菜单；SOP 放在会话接待右侧，后续任务进入工单处理 |
| SOP 全部节点先展示，不隐藏 | 固定节点始终列出；未触发、不适用、完成和异常均有文字状态 |
| 退换货诉求触发节点，点击后查看订单并预填 | 节点内展开办理详情，经客服核对和确认后登记申请 |
| 特殊咨询动态提供推荐文案 | 看板内增加动态建议卡，展示知识来源、适用说明与可编辑草稿 |
| 客户离线后关闭会话并记录遗留事项、回访 | 离线进入待结束处理；客服核对未完成项和回访安排后关闭 |
| 保留现有客户服务，再增加手机形式 Tab | 顶部增加“手机端演示”；左侧手机交互，右侧空白 |

布局、续答轮数、等待时间、节点和关闭方式集中列于第 8 节。本文描述本地原型的设计与实现；问答和续答使用确定性规则、已发布样例知识与本人订单记录。真实模型、在线心跳、外部退换货接口与消息通知均未接入。

## 2. 当前实现与职责

默认入口是 `index.html` 与 `src/`。客户服务与手机端演示共用客户角色；客服工作台和运营后台按各自角色范围处理同一份本地业务记录。

| 界面或能力 | 当前行为 |
| --- | --- |
| 客户服务、手机端演示 | 共用当前会话、本人订单、公开工单、反馈和未发送草稿；手机右侧留白 |
| 会话接待 | 会话列表、消息区与 SOP 并排；一线菜单保留会话接待、工单处理 |
| SOP 看板 | 8 个固定节点、退换货 4 个常显子步骤，问题分别归属与切换 |
| 人工阶段 AI | 当前接待人明确开启，等待 30 秒，单次最多 2 轮，人工输入优先 |
| 退换货受理 | 核对订单、类型、原因和换货要求，预览后确认；重复操作复用原记录 |
| 离线与关闭 | 显式模拟连接状态；未完成项安排、关闭小结与业务快照一并保存 |
| 回访 | 依附工单，继承负责人及权限，支持未来计划、改期、结果与转派 |

单纯为遗留事项建立的跟进工单使用 `followupOnly` 标记，不代表售后申请已登记，不能把退换货步骤标为完成。资料核对齐全后，可通过结构化受理沿用跟进单，保留编号、负责人和历史。真实退款、发货、换货执行及资格审批均不由本地原型完成。

## 3. 客服工作台：会话与 SOP 并排

### 3.1 页面结构

顶部工作区按“客户服务｜手机端演示｜客服工作台｜运营后台”排列。客服工作台内部保留原来的两个菜单。

```text
客服工作台 / 会话接待
┌──────────┬──────────────┬──────────────────────┬──────────────────┐
│ 会话接待 │ 待接待       │ 客户编号 · 接待状态   │ SOP 看板         │
│ 工单处理 │ 我接待中     │ 消息时间线            │ 当前问题 / 订单  │
│          │ 我的历史     │                      │ 全部固定节点     │
│          │ 搜索与会话列表│                      │ 展开的节点详情   │
│          │              │                      │ 动态建议         │
│          │              │ 公开回复 / 内部备注   │ 客户资料入口     │
│          │              │ 输入框 · AI续答控制   │                  │
└──────────┴──────────────┴──────────────────────┴──────────────────┘
```

在 1440px 桌面上，左侧导航约 160px、会话列表约 220px、SOP 看板约 380px，聊天区占剩余空间。1280px 时适当压缩导航和会话列表，优先保证聊天输入和 SOP 操作可用。窄屏允许整个工作区横向滚动，不能为了适配而隐藏 SOP 节点。

聊天消息、会话列表和 SOP 内容分别滚动。右侧标题与当前问题信息保持可见；底部输入框不被节点详情遮挡。节点状态更新不自动跳转页面、不打断客服正在编辑的内容。

### 3.2 看板内容与节点展开

看板顶部展示当前客户问题、关联订单、接待模式及“待处理节点数”。同一会话有多个问题时，顶部列出问题切换项；切换只改变正在查看的 SOP，不合并不同问题的状态。每个问题都展示完整固定节点目录。节点 1—7 的进度归属客户问题；节点 8“结束沟通”是会话级控制入口，在不同问题看板中展示当前会话的同一状态，不为每个问题分别创建关闭任务。

节点行展示：顺序号、节点名称、文字状态、触发原因和主操作。点亮节点使用强调色，并显示“客户提出退换货，待核对订单”等可理解的原因；颜色不能作为唯一提示。

点击任一节点，可在节点下展开详情；同一时间展开一个详情区。其他节点的名称和状态始终保留在列表中，可通过右侧滚动查看。再次点击收起，或点击另一节点切换；未提交内容按客户问题和节点分别保留。

客户资料、交接摘要、问题关联和订单信息均可访问：客户资料放在看板底部，摘要放在“确认诉求”，订单信息放在“核对订单”。内部备注、知识依据和工单入口保留在对应消息、节点和记录中。

### 3.3 固定节点目录

固定目录如下。所有节点默认可见；未触发节点可打开查看说明，但不能伪装成已办理。

| 节点 | 点亮条件 | 展开内容与主要操作 | 完成依据 |
| --- | --- | --- | --- |
| 1 确认诉求 | 新问题进入或客户补充改变原诉求 | 原始消息、AI 摘要、诉求类型；客服可纠正、关联已有问题 | 客服确认，或明确规则已识别并记录依据 |
| 2 核对订单 | 查物流、退换货等需要订单的问题 | 本人订单列表、商品、金额、状态；选择并确认订单 | 当前问题关联唯一且归属核对通过的订单 |
| 3 查询物流 | 明确物流查询 | 当前物流信息和查询时间；可将查询结果插入回复 | 查询成功并记录所用订单与查询时间；无法核对时提示错误，不记录查询成功 |
| 4 退换货办理 | 明确退货或换货诉求 | 类型、原因、订单详情、规则依据、已有申请；核对并登记 | 结构化确认后生成或沿用正式受理记录；纯跟进任务不计为登记 |
| 5 补充资料 | 已触发流程缺少必要信息 | 缺少什么、已知什么、建议追问；等待客户补充 | 必填信息经核对齐全，或明确记录不再需要的原因 |
| 6 记录处理结果 | 可以答清问题或有办理结果 | 客户可见结论、内部核对依据；已有工单时打开原工单处理 | 结果及依据保存成功；客户是否确认另行显示 |
| 7 回访安排 | 客服选择需要回访，或明确服务承诺需后续核实 | 回访目的、时间、负责人、关联工单 | 回访任务保存成功；任务本身是否完成另行跟踪 |
| 8 结束沟通 | 客服主动结束，或客户离线进入待结束处理 | 接待小结、未完成项、后续任务和回访 | 未完成项都有有效去向，关闭记录保存成功 |

这些节点是流程目录，不要求每个问题走完全部分支。单纯规则咨询时，订单、物流和退换货节点可以保持“未触发”；关闭时不会要求客服逐个填写无关节点。

退换货节点下方始终列出“确认类型与原因→核对规则及缺失信息→核对申请→登记受理”四个子步骤，分别显示进度。收起详情只收起说明和表单，子步骤名称与状态仍然可见。登记受理后仍可看到原申请和后续工单状态。

节点状态分为“未触发、待处理、处理中、待客户补充、已完成、不适用、异常”。转入后续任务的节点保留实际未完成状态，同时标明“已安排跟进”和工单编号。点击节点、插入草稿、发送普通消息，都不能自动把办理节点标成完成。

### 3.4 节点与客户问题的归属

AI 或规则识别出“我要退货”时，点亮退换货节点并提示所依据的原始消息。已存在同一订单的未完成售后事项时，推荐继续原事项；意图或订单不明确时，显示“待确认”，由客服选择。

同一条消息包含多个订单时，不自动选第一个订单。客服逐一确认对应问题，避免把甲订单的草稿、金额或状态带到乙订单。已触发节点可由客服纠正为“不适用”，须记录原因；修正不能删除已经提交的申请或业务历史。

同一问题在新会话继续时，沿用节点 1—7 的原业务进度、工单和首次受理时间；节点 8 根据当前会话重新显示，不能继承上一段会话的“已结束”。新问题建立独立进度。客户提出异议时，只恢复受影响的节点；原已完成结果与关闭记录保留供回看。

## 4. AI 续答、动态建议与退换货办理

### 4.1 AI 先接待与繁忙续答

接待主流程为“自动接待→人工排队→人工接待”。排队保留承接说明，人工阶段通过明确授权提供有限续答。

| 情况 | AI 行为 | 客服可见反馈 |
| --- | --- | --- |
| 客户首次进线 | 先回答有依据的规则问题、查单或收集办理信息 | 已识别诉求、已完成动作和待补充内容进入 SOP |
| 客户已要求人工、仍在排队 | 允许一次承接说明和必要资料采集，人工请求持续保留 | 显示“等待人工，AI 协助采集”；不能把排队改成已解决 |
| 已接管，客服开启繁忙续答 | 在未回复的新客户消息上，等待达到设定时间后有限续答 | 显示当前续答状态、剩余轮数、每条答复及依据 |
| 客服开始输入、发送、点击暂停或会话转派 | 立即停止待发送的 AI 回复；人工发送优先 | 显示“人工接待”；未发送 AI 文案可留为建议 |
| 没有可靠依据、信息冲突、达到轮数上限 | 停止自动回答，给客服待处理提醒 | 突出需要核实的问题，不能反复发送相同等待话术 |

人工接管后自动发送默认关闭，客服可为当前会话开启“忙时 AI 续答”；等待 30 秒仍未回复时触发，单次授权最多续答 2 轮。“一轮”指客户有新的消息后，AI 发送一次有效公开回复；不能在客户沉默时连续自说自话。开启后若客服重新输入，暂停续答；恢复需要客服再次明确开启。

AI 使用与客服一致、礼貌简洁的服务口吻。客户侧仍以“在线客服”作为服务入口，自动消息保留轻量“AI 协助”标识；内部明确记录实际发送者、授权客服、依据及发送时间，不能把 AI 消息记作人工亲自回复。人工首响统计也不能由 AI 续答停止计时。

自动续答只覆盖有依据的解释、已授权订单信息与缺失资料采集；退换货申请提交、金额或资格承诺、记录最终办理结果和关闭会话仍需相应确认。客户明确要求停止自动回复时立即停止，并保留人工待办。

发送前重新核对当前会话、最新客户消息、接待权、知识有效性及版本、当前订单事实和关联关系。期间人工已回复、客户补充或改口、知识被停用或失效、知识版本更新、订单事实或绑定变化、会话转派或关闭、客户离线时，取消过时答复；不能把另一客户或上一条问题的结果发出去。每条客户消息只触发一次对应续答，失败不会重复发送。

### 4.2 动态知识建议

固定流程节点下方设“动态建议”区。非标准咨询、知识问题或信息不足时，依据当前问题、最近消息、已选订单及有效知识生成建议。动态建议可以与固定节点同时出现。

每张卡片展示：针对的问题、建议回复正文、知识标题和版本、来源、适用限制，以及“插入公开回复”“查看依据”“暂不采用”。新建议出现时显示一次提示，保留已经人工编辑的草稿。

“插入公开回复”只填入输入框，由客服编辑后发送。输入框已有内容时提供“追加、替换、取消”；选择替换前展示待替换内容，不自动清掉手写文本。内部备注不作为公开回复预填来源。

匹配不到知识时显示“暂无可靠建议”，提供收集信息的追问建议和“标记服务问题”；来源冲突时列出冲突提示并交客服核实。不能凭空生成政策、订单状态或退款承诺。已发送的建议保留当时知识版本。新消息、知识停用／过期／版本更新、订单事实或问题关联变化，都会使未发送建议失效，标注“需要重新核对”；采用建议时重新检查这些依赖。已经插入并人工编辑的草稿保留正文，但发送前须核对更新后的依据并确认，不能把失效推荐当成仍然有效的内容直接发送。

动态建议的“已采用”仅表示文案被发送或使用，不代表对应 SOP 或客户问题已经完成。自动续答即使参考同一知识，也单独遵守 4.1 的发送许可。

### 4.3 退换货办理详情与预填

示例：客户说“这个杯子漏水，我想换一个”，并提供本人订单号。看板点亮“核对订单、退换货办理”；订单已经可靠关联时可直接进入退换货详情。

| 字段 | 默认与来源 | 规则 |
| --- | --- | --- |
| 客户、当前问题 | 当前会话与已确认问题 | 只读；不能切到其他客户提交 |
| 关联订单 | 优先使用当前问题已确认的本人订单 | 必填；无法唯一识别时留空，由客服选择 |
| 商品、订单金额、订单状态 | 关联订单事实 | 只读；金额是订单金额，不视为可退金额 |
| 服务类型 | 明确“退货”预填退货退款，明确“换货”预填换货 | 必填；含糊表述留空，客服确认 |
| 申请原因 | 客户明确描述，附原消息入口 | 必填，最多 2000 字；AI 提取内容标“待核对”，客服可改 |
| 换货诉求 | 客户明确表达的更换要求，供提交人核对 | 换货时必填，最多 200 字；只预填可明确识别的要求，含糊或未说明时留空，不默认库存充足 |
| 补充说明 | 无默认值 | 可选，最多 1000 字；仅填写与申请相关的信息 |
| 规则与待核信息 | 有效知识及已知订单事实 | 显示依据和版本；缺少签收时间等条件时标“待核实” |
| 已有申请 | 当前问题及订单关联的受理记录 | 展示编号与状态，可进入原工单继续处理 |

预填字段用“来自订单／客户原话／待核对提取”区分来源。未知信息留空；有可参考的规则不等于已确认符合条件。更换订单时，订单事实随之更新，依赖原订单的核验结果失效；客服手填的原因和说明保留并提示重新确认，不静默覆盖。

操作流程为“核对订单与信息→核对申请摘要→确认登记”。摘要展示将提交的服务类型、订单、原因和换货诉求；返回编辑保留全部字段，取消不创建申请。确认时重新检查归属、当前办理权和已有申请。

同一问题已有未完成工单时进入原单，不能因为切换 Tab、重复点击或新增 SOP 提示而重复建单。返回页面后展示实际保存的工单编号。保存失败保留输入，不点亮完成状态。登记完成的面客提示为“申请已登记，待核实处理”，实际退款、换货和寄回安排由后续业务办理。

## 5. 客户离线、结束记录与回访

### 5.1 离线与会话关闭

客户在线状态与消息是否回复分开记录。区分“在线、连接中断待确认、已离线”；暂时无新消息、切换产品 Tab 或手机屏幕隐藏，不能直接判定客户离线。

确认离线后暂停 AI 续答，接待页提示“客户已离线，请整理本次沟通”，点亮“结束沟通”。由客服确认关闭；在未完成事项得到安排前，页面保持“待结束”，不能静默结束并丢掉办理责任。

本地演示增加明确标为演示用途的“模拟离线／恢复在线”控制，只改变当前客户的模拟连接状态。真实心跳、断网判定和跨设备在线状态属于后续接入。恢复在线或客户发来新消息时，取消待结束提示；已打开的关闭面板需重新核对最新消息才能继续提交。

### 5.2 结束沟通面板

客服点击“结束沟通”后，展示一张可核对的结束面板。

| 区块 | 内容和操作 |
| --- | --- |
| 基本信息 | 客户、会话、接待人、开始时间、结束原因（问题已答复／客户离线／转后续办理／其他） |
| 接待小结 | 自动汇总已讨论问题和已办动作，客服可编辑；必填，最多 1000 字 |
| 未完成项 | 列：客户问题、SOP 节点、当前状态、未完成原因、后续安排；只纳入已触发且未完成的业务节点；排除“结束沟通”控制入口 |
| 后续安排 | 每项选择继续已有工单、建立跟进工单、登记回访，或客户撤回／确认为不适用；选择后展示关联编号或必填原因 |
| 回访 | 默认无需回访；需要时填写下表字段，并明确关联哪些未完成项 |
| 确认区 | 展示将保留的未完成项及任务数量；“返回接待”“保存记录并关闭” |

未完成项不会仅因填写了一句备注就算安排妥当。需要继续办理的事项必须落到可追踪的工单，写清负责人及目标时间；回访可作为该工单的后续动作。规则咨询等仅需联系确认的事项，可新建“回访跟进”工单。多个相关节点可共用同一跟进工单，界面列出关联关系，同单的目标时间须一致。纯跟进任务只承接核实责任，不补记未发生的售后登记或业务结果。

“客户撤回／不适用”只用于确实无需继续的步骤，须记录依据。已经受理的退换货不能通过此选项直接撤销；仍须在原工单中按办理规则记录。

无未完成项时，可直接核对小结并关闭。未触发的分支和单纯未采用的知识建议不进入必填清单。关闭时保存 SOP 业务状态快照、小结、遗留项及任务关联；它们和会话关闭必须一并成功。“结束沟通”在本次关闭成功后记为完成，不作为关闭前必须安排去向的遗留项。失败时保留编辑内容，会话保持打开。

### 5.3 回访记录与执行入口

| 字段 | 默认与校验 |
| --- | --- |
| 客户、问题、关联工单 | 从当前上下文带入，提交前展示；不能跨客户关联 |
| 回访目的 | 必填，最多 1000 字；例如“确认是否收到换货处理说明” |
| 计划时间 | 必填，晚于当前时间；显示年月日、时分和时区，统一为北京时间 UTC+08:00 |
| 负责人 | 必填，只读继承关联工单负责人；新建回访跟进工单默认当前客服。已有工单未分配时，先领取或分配再保存回访 |
| 联系方式 | 首期登记为站内联系；不自动拨号、发短信或推送 |
| 补充备注 | 可选，最多 1000 字，仅内部可见 |

首期回访与关联工单使用同一负责人及可见范围，一线只能为本人负责工单新增回访、改期或登记结果。需要其他客服接续时，通过既有工单转派流程调整，未完成回访随工单同步转移，历史执行记录保留。结束面板可以引用其他客服已经负责的有效工单安排，但不能越权修改其回访。

回访沿用“工单处理”入口，不新增一级菜单。列表增加“待回访／已到期”筛选和最近计划时间；表格依次展示工单与问题、状态、负责人、受理时间、处理目标、回访时间、操作。到期任务持续提示，不能因原会话关闭或刷新消失。

负责人点击“登记回访结果”，填写联系结果（已联系／未联系上／取消）、结果说明；未联系上须安排新的未来时间，取消须填写原因。仅登记回访结果不自动办结售后或确认客户已解决；需要办理结论时仍走工单结果流程。

会话历史可查看每次关闭的小结、当时节点状态和关联回访。客户再次咨询时，根据问题和订单关联原记录；历史关闭快照保持原样，后续更新落在当前进度和工单中。

## 6. 手机端演示 Tab

### 6.1 布局

这是产品顶部的展示 Tab，与现有客户服务页并存，代表同一个客户端的另一种布局。

```text
客户服务  |  手机端演示  |  客服工作台  |  运营后台

  演示状态：在线  [模拟离线]
  ┌───────────────────────┐
  │ 状态栏                │
  │ 在线客服              │
  ├───────────────────────┤          右侧空白
  │ 智能答复 / 人工答复   │          不放说明卡、图表、配置或占位文案
  │ 客户消息              │
  │ 订单与售后卡片        │
  │                       │
  ├───────────────────────┤
  │ 常用服务入口          │
  │ 输入框          发送  │
  └───────────────────────┘
```

手机框靠左放置，不在整页居中。内容视口采用 390:844 的纵向比例，配圆角和轻量设备边框，作为手机布局示意，不绑定具体 iPhone 型号。可用高度不足时等比缩小外框；消息区独立滚动。实际窄窗口下宽度贴合可用区域，字体和点击目标保持可操作。

右侧是无内容的页面背景，不设置大面积“敬请期待”占位、未来面板或说明文字。演示控制放在手机框上方的左侧区域，并明确与手机内客户界面区分。

### 6.2 手机内的交互

| 位置 | 显示与动作 |
| --- | --- |
| 顶栏 | “在线客服”、当前智能／人工／等待接待状态；菜单内提供历史咨询和新咨询 |
| 消息区 | 客户、AI、人工回复及时间；知识来源可打开；只显示客户可见内容 |
| 快捷入口 | 服务规则、我的订单、服务进度、联系人工；放在输入框上方，不挤占整屏 |
| 我的订单 | 手机内底部抽屉展示本人订单；可查物流、申请退换货 |
| 退换货申请 | 手机内全高面板填写和核对；返回保留输入，确认后显示受理编号与进度 |
| 服务进度 | 展示本人办理记录；可补充信息、查看公开结果、确认解决或继续求助 |
| 输入区 | 文本输入、发送、空值校验及发送失败反馈；长文本可换行，消息与表单分别滚动，发送及确认可操作；真实 iOS 软键盘需另行验证 |

手机面板的弹层限制在手机内容区域内，不覆盖右侧留白或把桌面式大弹窗放到整页中央。申请预览的“返回修改”恢复表单和已有字段；关闭弹层回到当前聊天并保持阅读位置。新咨询或切换历史会话时显示所选会话的消息。

内部 SOP、知识草稿、客户隐私字段和核对备注不得出现在手机端；客户看到的是自己的消息、订单、申请和公开处理结果。模拟离线时保留输入但停止发送，显示“连接已断开”；恢复后可继续发送，不自动清空或补发未确认内容。

### 6.3 与现有页面共用记录

现有客户服务页与手机端演示共用客户身份、当前会话、订单、工单、反馈和未提交客户草稿。在手机里发出的问题，切到客服工作台能看到；客服回复后，切回手机看到同一条回复，不复制另一套样例。

切换到现有客户服务页继续同一会话，不创建新咨询、不重播欢迎语。只有明确点击“新咨询”才新建记录。关闭和恢复 Tab 不等于客户离线。

手机页使用客户角色的展示模式，复用客户数据范围和动作校验。只渲染当前活动视图，避免两个输入框或相同 ID 的弹层同时存在。草稿按客户、会话和表单分别保存，并与客服内部备注隔离。

首期支持同一浏览器页面内的工作区切换。不同浏览器标签页、多设备实时同步和真实手机推送不计入本地演示的完成条件。

## 7. 验收清单与实现落点

以下定义各场景的可观察结果。实际执行状态、截图和限制以[验收矩阵](验收矩阵.md)及[SOP/手机端验收证据](../tests/evidence/sop-mobile-review.json)为准，场景定义本身不代表已经通过。

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| A01 | 打开客服会话接待 | 两个一级菜单保留；聊天与右侧 SOP 同屏，固定节点全部列出 |
| A02 | 仅咨询规则 | 有适用建议；物流、退换货等未触发节点仍可见，关闭不强制处理无关步骤 |
| A03 | 客户明确申请换货 | 相关节点点亮，可追溯触发消息；展开显示订单、待核对原因和完整子步骤 |
| A04 | 没有订单号／出现两个订单号 | 要求选择或补充；不擅自绑定首个订单，不跨客户查询或提交 |
| A05 | 预填后人工改写，再收到新消息或切换会话 | 手写草稿保留；新信息提示核对，不能覆盖或串到另一客户 |
| A06 | 核对申请取消、重复确认、已有未完成工单 | 取消不建单；重复操作只返回同一受理记录；已有原单继续处理 |
| A07 | 人工开启续答后暂未回复 | 等待 30 秒后可续答，最多授权轮数；明确展示实际发送者 |
| A08 | AI 待发送时人工输入、客户补充、知识失效或更新、订单变更、转派、关闭或离线 | 过时回复被取消；建议采用前重新核对；人工优先，没有重复答复；AI 不停止人工首响计时 |
| A09 | 奇怪咨询无知识／来源冲突／已有回复草稿 | 显示待核实；不编造结论；插入时有追加、替换、取消，手写内容受保护 |
| A10 | 客户模拟离线，SOP 尚未完成 | 出现待结束提示；逐项记录原因、工单与责任人；无有效去向不能关闭 |
| A11 | 关闭面板期间客户回到在线或有新消息 | 提示重新核对，不按旧快照静默关闭 |
| A12 | 关闭时保存失败／刷新／重复提交 | 结束入口不被当成遗留项而阻塞自身；会话不被半关闭，输入保留；成功后关闭记录与跟进任务一致且不重复 |
| A13 | 安排回访、关闭并转派原工单 | 回访与工单负责人一致，转派后新负责人可见并可执行、旧负责人失去修改权；到期、未联系上、改期、取消均有记录 |
| A14 | 客户在已关闭问题上再次咨询或提出异议 | 原工单和历史关闭快照保留，当前关联进度正确恢复 |
| A15 | 切换手机端、客户服务、客服工作台 | 同一咨询、回复、订单、草稿与工单连贯；手机页只有客户可见信息 |
| A16 | 手机内展开订单、售后表单和历史咨询 | 弹层在手机内，输入与确认可点击，返回位置和草稿正确；右侧始终空白 |
| A17 | 既有浏览器记录升级后继续使用 | 原编号、受理时间、手写消息、知识版本、内部备注与草稿保留；既有业务与历史模块回归保持兼容 |

验收分两层记录：域测试与页面事件测试验证状态、权限、去重和草稿；真实 HTTP 浏览器检查验证 A01、A15、A16 的布局和跨页面操作，以及 A07—A14 的可见反馈。浏览器至少覆盖 1440px、1280px 桌面中的手机框，以及 390px 可用宽度，实际点击订单、表单、返回和发送，记录截图、操作结果、页面溢出及控制台异常。证据归入 [验收矩阵](验收矩阵.md) 和 [SOP/手机端验收证据](../tests/evidence/sop-mobile-review.json)，逻辑测试通过不能代替这些检查。首期验收对象是浏览器中的手机界面演示，真实 iOS 键盘、设备网络与推送需另做真机验证。

所有自由文本去除首尾空白后校验，必填不接受全空格；保留正文换行、中文标点和普通表情，按文本显示。字段长度与条件必填按本地表单及领域命令校验。未知值留空并说明原因，加载、无记录、查询失败、提交失败各有明确反馈。

## 能力与验证边界

本地规则负责可解释的关键词命中、路由和信息收集，不代表真实模型的语言理解与泛化能力。客户在线状态是显式演示状态，没有真实设备心跳。订单和知识均为虚构样例；受理、结果和回访只保存本地记录，不执行退款、发货、短信或推送。页面角色切换不等于服务端认证或生产数据隔离。

测试、浏览器截图及异常场景的实际覆盖统一查看[验收矩阵](验收矩阵.md)与[SOP/手机端验收证据](../tests/evidence/sop-mobile-review.json)。真实 iOS 软键盘、设备网络及通知未验证；JSON 导出下载落盘、再次读取及 `file://` 下的存储行为需单独验证。单文件可构建不等于上述环境均已验收。
