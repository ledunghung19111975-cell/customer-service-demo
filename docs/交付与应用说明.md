# V4 交付与应用说明

产出 Agent：Codex。集成、主写、参与与最终收敛 Agent：Codex。用户附件原始产出平台未标明。

## 运行条件与入口

使用现代浏览器和 Python 3。日常演示无需 Node.js、模型密钥或外部服务。在项目目录运行：

```bash
python3 run.py --no-open
```

打开 [客户服务](http://127.0.0.1:8768/#customer)，通过顶部切换到[手机端演示](http://127.0.0.1:8768/#mobile)、客服工作台或运营后台。手机 Tab 是同一客户角色的展示模式，共用咨询和草稿，不新增身份或另一套业务数据。独立面客页为 [服务中心](http://127.0.0.1:8768/?view=customer#customer)，不显示工作区切换。产品名称为“智能客服”，咨询窗口显示“在线客服”；样例客户按编号标识，一线客服为客服 01 / 02。运营页面依当前角色显示可用菜单，服务概览由“服务经理”查看。

脚本只监听本机，默认端口为 8768，省略 `--no-open` 会自动打开页面。按 `Ctrl+C` 停止服务；端口占用时不会自动换地址。需要改端口可使用 `python3 run.py --port 8769 --no-open`，新端口对应另一份浏览器数据。

## 单文件交付

从可读源码生成自包含页面：

```bash
python3 build_single.py
```

产物为 `dist/智能客服.html`，包含 V4 所需脚本与样式。通过本地服务访问 [单文件页面](http://127.0.0.1:8768/dist/智能客服.html) 可维持相同浏览器来源；与源码入口同源时会使用同一保存键。单文件不包含旧版运行时。

直接双击 HTML 的 `file://` 存储行为取决于浏览器，不能据此保证跨文件或跨浏览器保存。需要复现刷新与存储验收时，以稳定的 HTTP 地址为准。

## 操作范围

客服左侧保留“会话接待、工单处理”。会话右侧常显 8 个 SOP 节点，退换货节点下 4 个子步骤常显；点击只展开详情，不代表办理完成。客服接管后可核对订单、查询物流、查看知识建议、结构化登记退换货及记录结果。

人工阶段 AI 续答默认关闭，当前接待人明确开启后等待 30 秒，每次授权最多 2 轮，每轮需要新客户消息。人工输入或发送、暂停、转派、关闭和客户离线会阻止待发内容；标为“AI 协助”的回复不记作人工首响。演示采用本地规则与固定知识，不需模型密钥。

“模拟离线／恢复在线”只修改当前客户的演示连接状态；离线保留草稿并阻止发送，不自动关闭会话。客服保存关闭记录前，为每个未完成节点安排原工单、跟进任务或回访。跟进任务 `followupOnly` 不代表正式售后登记；结构化确认后才沿用该单登记。回访继承工单负责人，未联系上须填写下次未来时间；转派不改写历史关闭快照。

## 数据管理

V4 使用 `qinghe-support-v4`，界面选择与未提交草稿另存在当前会话的 `sessionStorage`。同一标签页切换工作区继续使用同一业务记录；刷新后由浏览器保存值恢复。

已有 V4 记录中的指定内置默认文案由 `src/copy.js` 精确更新。更新只处理可识别的内置字段，保留会话、订单、工单编号、状态、归属、受理时间和业务关系，手写消息、内部备注、知识草稿和表单草稿原样保留。

更新前将原始保存字符串原样写入 `qinghe-support-v4:before-copy-v1`，不通过解析和重新序列化生成备份。相同原值已有备份时复用；若此前尝试已留备份、记录随后又发生变化，则使用 `qinghe-support-v4:before-copy-v1:1`、`:2` 等后缀另存当前原值，已有备份不覆盖。备份写入或校验失败时停止更新。知识来源等已发布依赖变化后，缓存的知识与策略回归结果失效，需要重新测试。

系统管理员在“数据维护”可导出当前工作空间 JSON，或导出旧保存键 `zhixu-customer-demo-v3.1` 的原始值。旧数据不自动迁移。需要继续查看或使用旧版时打开 [legacy.html](http://127.0.0.1:8768/legacy.html)，旧版操作与 V4 分开保存。

V4 不提供数据导入或业务清空界面。准备全新演示数据时使用新的浏览器配置或明确选择的测试来源，不清理日常浏览器中的已有数据。读取异常时保留原始内容；保存失败或检测到其他页面更新时阻止当前写入。

## 验证方式

逻辑测试需 Node.js：

```bash
node --test tests/domain.test.cjs
node --test tests/workflow.test.cjs
node --test tests/v4-ui.test.cjs tests/workbench-ui.test.cjs tests/workbench-review.test.cjs
node --test tests/copy.test.cjs
node --test tests/*.test.cjs
```

专项命令分别验证业务域、SOP 与授权/回访、页面事件及默认文案更新；最后一条还包含历史模块回归。文案测试覆盖精确匹配、原始值备份、失败保护和用户内容保留。测试总数不是 V4 测试覆盖数，具体层级和真实浏览器证据见 [验收矩阵](验收矩阵.md) 与 [SOP/手机端验收证据](../tests/evidence/sop-mobile-review.json)。旧 Python 浏览器脚本及历史截图不用于判定 V4 通过。

`index.html` 只加载 `src/`；根目录旧 `app.js`、`engine.js`、流程画布等文件由 `legacy.html` 使用，供旧版访问与历史参考。检查分发物时应验证实际打包文件，不将旧哈希清单或附件环境结论套用于当前文件。

## 使用边界

本地角色切换不提供登录认证。所有客户与订单是虚构样例，知识与策略使用规则模拟，处理结果只写本地记录。没有真实订单、退款、支付、邮件、短信、大模型、在线心跳或多人同步。真实 iOS 键盘、设备网络与推送未验证；管理员导出入口不等于下载文件已落盘并可再次读取，这一环节须单独验证。不要录入真实客户资料、支付信息或凭证。

交付范围是本地源码、单文件生成能力和本机验证；远端同步、公开托管与生产上线需要单独执行并验证。演示路线见 [演示脚本](演示脚本.md)。
