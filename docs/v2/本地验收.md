## SOP 与历史消息

八步 SOP 看板仍保留在 `ecommerce-v1.html`，节点为确认诉求、核对订单、查询物流、退换货办理、补充资料、记录处理结果、回访安排、结束沟通。V2 右侧“服务处理”面板提供事项办理操作及澄清诉求的三步指引（确认具体诉求、补齐必要信息、记录处理结果），尚未接入完整八步 SOP 状态流。指引不自动判定各步骤完成；办结依据来自客服登记的处理结论。

新人工回复保存发送者 ID 与姓名。旧记录没有发送者字段时，仅在首条人工回复时间及唯一关联消息一致时展示为人工客服；证据不足的旧系统消息保留原身份，不根据正文猜测，不改写浏览器保存数据。

## 证据边界

附件中的 70 项业务、17 项浏览器与 12 项安装检查属于原始交付证据。这里的 Node 和 Python 结果来自本机复跑。附件浏览器脚本未在本机完整重跑：本机没有 Python Playwright；脚本使用内存 Storage 和编辑锁测试替身，仅能验证内嵌页面的交互。原生保存与排他锁由上述实际 HTTP 页面检查独立验证。

页面验证没有覆盖完整 17 项附件流程、真实图片上传全链路、真实移动设备或跨浏览器矩阵。退货退款、换货补发等状态链有业务自动化覆盖；实际订单、支付、仓库、通知、生产鉴权及多人协同仍未接入。原生锁不支持的浏览器保持只读，建议通过现代浏览器的本地 HTTP 来源编辑。
