## 设计到实现

| 修订点 | V2 行为 | 实现位置 |
|---|---|---|
| 多诉求分开、正常物流先查询 | 同句知识和包裹诉求分别保存；普通在途不自动升单 | service.js：路由、查询、事项记录 |
| 商品和优惠 | 商品属性展示、澄清；本人订单与优惠券资格查询 | model.js：商品活动样本；service.js：couponResult/retrieve |
| 取消改址 | 草稿预览、本人确认、最新履约校验、独立变更回执；退款单独跟踪 | service.js：preview/confirm；app.js：订单及变更表单 |
| 分类售后 | return_refund、refund_only、exchange、reship；目标规格和缺失内容分别收集 | model.js：类型与规则；service.js：校验及审批 |
| 申请材料 | 本地图片选择、类型与大小校验、复用与补件；客服整理草稿，用户确认 | app.js：表单与上传；service.js：addAttachment/prepareDraft/supplement |
| 寄回和复核 | 审核后显示寄回信息；收货、验收、异常补件、复核恢复各有记录 | service.js：approve/receiveReturn/inspect/resolveInspection |
| 退款保护 | 原请求提交/查询，未知结果继续占用，重复和过期回执不重复执行 | service.js：submitRefund/queryRefund/recordRefundReceipt |
| 人工接续 | 接管、公开回复、内部备注、接收前保留责任；转派同时接续同会话相关未完事项 | service.js：claim/handoff/acceptHandoff；app.js：工作台 |
| 场景配置 | 按类型保存草稿、验证、发布，实际改变新申请，原申请保留规则快照 | service.js：savePolicy/testPolicy/publishPolicy；app.js：场景配置 |
| 知识质量 | 条目草稿、正反例测试、发布、停用及原问题复验记录 | service.js：知识与整改命令；app.js：知识库/质检整改 |
| 解决指标 | 答复不直接算解决，异议单列，人工审批/验收/财务办理排除 AI 独立解决 | service.js：metrics；app.js：服务看板 |
| 发票、价保、维修 | 分类字段、预览确认、审核与进度；没有伪造已开票或已补差 | service.js：对应申请类型；app.js：其他服务表单 |

以上源文件均位于 `src/v2/`。此交付采用独立 V2 运行模块与默认入口，不改写原运行模块；安装时保留旧源码和旧入口。并未完成旧数据迁移，也未把旧代码的全部测试结果并入 V2。
