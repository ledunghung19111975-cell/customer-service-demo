## 发布面板的回归用例

R01/R02 为否定和咨询不误采集；R03 为缺参；R04 为查询与办理分开；R05 为正常查询返回样例或按配置分支明确转人工；R06 为未知对象不生成结果；R07 为多事项保留知识；R08 为实时离线；R09 为工具停用；R10 为演示归属负例。

S 开头的用例检查答案来源稳定性：从 R 系列问句及当前有效 FAQ 的标准问题中，筛出原配置实际产生知识引用的样本，要求草稿仍引用同一条知识。已停用、过期或原配置本就没有引用的样本不进入这组稳定性检查。它拦住新知识用重叠关键词抢答存量问句，也拦住流程参数改动让存量 FAQ 答不上；本版没有“确认变更答案来源”的豁免入口。

知识作答门槛：至少命中 2 个关键词，或问题包含标准问题；只沾一个泛词（如“退款多久到账”“保温杯可以放洗碗机吗”）按未命中转人工并生成线索。关键词只能判断主题、判断不了具体问点：“退货规则里运费谁承担”同时命中“退货、规则”，仍会给出七天无理由规则原文。这是关键词检索的能力边界，需要语义检索与可答性判断，本版不宣称解决。

知识草稿在路由用例与稳定性检查之外，增加标准问题应引用目标知识的检查，以及关联整改原问题的检查。回归结果是执行器实际输出，不是硬编码的“通过”徽标；同时它只检验这些不变量与引用，不自动判断答案事实是否正确。

## 仍需补做的环境验收

不同访问地址隔离、本地存储限制、多标签页冲突与跨浏览器兼容仍需验证；再在服务端环境验证身份权限、持久化、幂等、接管互斥、接口故障与通知。接入模型后另建语义、检索、回答与任务评测。

没有真实客户、接口或模型时，不填写伪造的性能指标和上线结论。仅以上述证据范围通过 V3 前端演示验收。


## 2026-09-26 HTTP 页面验收

产出 Agent：Codex。使用本机静态 HTTP 服务与内置浏览器，通过实际页面控件验证：

- 十页导航和 1280px 桌面布局，无页面横向溢出。
- 否定转人工的规则咨询、查询物流与售后分别建事项、预览确认后受理。
- 工单分配、完成说明及内部证据，客户仅看到公开说明并逐项确认结果。
- 刷新后同一工单和事项确认状态仍保留，使用真实浏览器存储。
- 工具停用后旧草稿试问失效，重测显示人工兜底。
- 关闭自助售后、十条发布回归、模拟发布、新会话绑定 v2，客户不显示自助售后按钮。

浏览器未返回控制台 error/warn。工作台截图已视觉检查。该验收未重跑 Python 离线套件，不覆盖移动端全尺寸、多标签并发、跨浏览器、真实模型或后端。该轮机器可读报告保留在 Git 历史；`local-review.json` 记录当前版本。
