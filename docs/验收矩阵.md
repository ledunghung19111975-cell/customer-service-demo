当前产品基线为 `index.html` 与 `src/` 的 V4 运行时，保存键为 `qinghe-support-v4`。`legacy.html`、根目录历史模块及其测试单列为旧版回归。用户附件的验收属于附件所在环境，不能直接作为本机 HTTP、原生浏览器存储或当前构建的通过证据。

## 功能与边界检查

| 编号 | 验收要求 | 检查方式与通过条件 |
| --- | --- | --- |
| V01 | 三工作区入口清晰 | 打开 `#customer`、`#desk/inbox`、`#ops/overview`；独立 `?view=customer#customer` 不出现工作区切换，内部菜单随运营角色变化 |
| V02 | 知识答复与客户确认分开 | 提问 `保温杯怎么清洗？` 后有来源引用、问题处理完成、不建工单；客户未点击前不计入明确确认 |
| V03 | 人工诉求与否定表述 | 明确要求人工进入队列；固定样本 `不要转人工，我只问退货规则` 保持知识处理；不将“人工智能”直接视为转人工 |
| V04 | 订单归属与补充续接 | 缺订单号时追问，插问知识后补本人订单仍完成原查询；他人订单不展示内容并转人工核实 |
| V05 | 多诉求分别记录 | `查物流 SO20260926002，再申请退货` 分别形成查询与售后问题，查询结果不替代办理结果；一条消息含多个不同订单号时交人工逐项核实，不自动绑定首单 |
| V06 | 申请明确确认与去重 | 填写、预览、确认才建单；取消无受理记录；同一问题已有未完成工单时复用；重复提交标识不能套用不同内容 |
| V07 | 接管、容量与回复权 | 未接管不能回复；暂离、关闭接待或满载不能领取；转派后旧负责人提交被拒绝；内部备注不停止首响计时 |
| V08 | 人工当场结果 | 无工单问题可记录公开结论和内部依据，不强制建单；已有工单必须通过工单记录结果；未完成且无人跟进时客服不能结束沟通 |
| V09 | 工单持续办理 | 领取后处理、请客户补充、补充后恢复办理；结束聊天不删除工单；完成结果需公开说明及内部依据 |
| V10 | 异议原单续办 | 客户填写未解决原因后原问题恢复，已完成工单重开；首次受理时间、编号、历史保留，概览完成数相应变化 |
| V11 | 客户可见范围 | 客户仅见本人订单、咨询和工单公开记录，不见内部备注、核对依据、执行过程与操作审计；该项只验本地视图 |
| V12 | 知识草稿与发布门槛 | 草稿不影响客户；正反例、日期、关键词与必填校验有效；回归通过且依赖指纹一致才发布，历史引用保留原版本 |
| V13 | 有限策略与隔离测试 | 必须保留明确人工触发；策略发布作用于新咨询；单条订单失败测试不改变业务记录或发布配置 |
| V14 | 服务问题复核与整改验收 | 未复核不能进入整改；知识发布并关联后，原题命中关联知识且全量规则回归通过才验收；存在草稿时拒绝验收 |
| V15 | 指标来源准确 | 完成与确认分别统计，异议重开不计当前完成；数据为空显示零，不展示虚构趋势、满意度或经营收益 |
| V16 | 保存失败与旧标签冲突 | 存储异常不覆盖原始值、不提示成功；其他页面更新后当前页拒绝旧状态覆盖；刷新验证已保存业务记录 |
| V17 | 旧数据隔离与导出 | V4 不改旧保存键；管理员可导出当前工作空间和旧版原始值；`legacy.html` 可访问旧运行时；实际下载内容另做浏览器核对 |
| V18 | 表单与页面可用性 | 必填和全空校验、取消无业务副作用、失败保留输入、切换与返回、375px 客户页和桌面布局、用户文本转义、浏览器控制台异常均实际检查 |

## 规则回归的能力边界

发布回归覆盖明确转人工、拒绝转人工、本人订单、他人订单、订单故障、多诉求和当前有效知识的正反例。待发布知识还检查生效区间。验收关联知识时另用原始问题验证命中。

这些检查验证确定性路由与状态约束，不自动审核政策事实，也不能保证未列自然语言样本的正确性。关键词可能匹配同一主题中的不同问点，正反例通过不等于语义覆盖完整。

## 未覆盖的生产条件

真实身份与撤权、服务端数据归属、多租户、数据库事务、分布式抢单、跨设备同步、外部订单与退款回执、消息通知、营业日历、真实负载及模型效果均未接入，不能判为通过。单页面顺序拒绝与旧标签冲突检查不构成多人并发保证。

本地实现验收通过。浏览器导出文件内容与原生 `file://` 存储未验证；历史 Python 浏览器脚本未运行，且不适用于 V4。
