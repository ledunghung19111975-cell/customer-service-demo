# 知序 · 智能客服工作台

产出、主写与收敛 Agent：Codex；参与 Agent：Codex（独立审查、使用文档）。

围绕客户咨询、订单查询、售后受理、人工接待、工单跟进和知识运营组织工作。会话、服务事项与工单分别记录状态；结束聊天不等于问题解决，登记售后不等于退款完成。

客户页提供咨询、订单、售后和历史咨询入口，后台提供接待与运营功能。实现边界和项目说明见下方开发文档。

## 本地启动

在项目目录运行：

```bash
python3 -m http.server 8768 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8768/` 进入运营工作台。

打开 `http://127.0.0.1:8768/?view=customer#playground` 进入客户页面。客户页面不渲染运营导航、坐席跳转、场景脚本或执行日志。后台“渠道预览”保留会话选择和折叠的执行记录，供运营检查接待流程。

运行时使用原生 HTML、CSS 与 JavaScript，无需安装 npm 包或构建。界面切换依然共享同一浏览器、同一访问地址的工作空间。演讲时使用一个标签页，返回后台后继续处理对应会话；不要把多个标签页并发编辑当成受支持的协作方式。

## 工作流程

客户可以直接描述问题，或从服务规则、订单物流、申请售后进入。订单操作会发送实际咨询请求，而不是只往输入框里填一条演讲示例。售后仍需要填写、预览和明确确认，才创建工单。结束咨询或发起新咨询后，可从“我的咨询”返回旧记录，跟进、补充或确认原工单。

运营工作台展示当前工作空间的事项、客户确认、待处理工单与复核待办。接管后由当前坐席回复。工单的客户说明与内部证据分开，处理完成后仍需要客户确认；客户异议进入复核或重开流程。

知识先保存草稿，再运行回归并发布。流程画布继续支持节点、连线、分支、发布门槛和历史版本。订单查询的故障响应只在“草稿测试”副本中设置，不写入待发布配置。已有版本遗留超时配置时，页面提供恢复草稿正常查询的操作，需要重新回归发布。

“系统设置”管理接待容量、服务组状态及工作空间数据。导出操作下载 JSON；清空需要二次确认，不会重新生成历史会话。成功清空后保留内置知识与接待配置。

## 开发与交付边界

这个仓库仍是轻量前端实现：问答使用本地规则与模板，记录保存在浏览器中。**没有接入真实大模型、RAG、外部订单系统、短信、邮件、支付或退款接口，也不具备服务端身份鉴权、多租户隔离、跨设备同步和多人并发保证。** 接入页面对尚未接入的能力如实显示“未接入”。

“青禾生活”、人物、订单、政策、业务结果均是为展示工作流程准备的虚构数据，不构成真实商家政策。不要录入真实客户资料、密钥或支付信息。界面的“内置服务”表示当前前端具备对应状态处理能力，不表示已经连接生产系统。

客户 URL 是界面入口，不是安全隔离。正式接入必须由服务端绑定客户身份、校验订单归属并落实操作权限。数据库、消息通知、真实 API、并发互斥和服务端幂等需另行实现。

## 数据兼容

继续使用 `zhixu-customer-demo-v3.1` 保存键，保留历史业务数据；内部兼容名称不作为界面文案。首次加载新版时，按精确文本匹配调整已知内置文案，不对任意用户内容执行全局替换，不改客户或坐席手写消息、不改自定义 FAQ 或未提交的表单草稿。

实际需要调整旧记录时，先把完整原状态备份到 `zhixu-customer-demo-v3.1:before-product-copy-v1`。备份失败则不执行持久化覆盖，并显示存储异常。数据无法读取时不覆盖原始保存值，临时空间与原记录分开；系统设置提供逐字导出原始保存副本。更新不重建已有事项编号、受理时间或工单状态。

由于已发布知识的内置措辞会发生变化，旧回归记录可能失去匹配条件，需要重新验证。不能把旧测试结果当成本次修改后的验证结果。

## 测试

逻辑测试需要 Node.js：

```bash
node --test tests/*.test.cjs
```

`tests/product-experience.test.cjs` 增加客户文案、售后受理边界、旧数据兼容与页面入口检查。

新的浏览器测试使用 Playwright 与 Chromium。在本地 HTTP 服务运行时执行：

```bash
python tests/product_browser_smoke.py --url http://127.0.0.1:8768
```

它使用独立浏览器上下文，不清空你日常浏览器中的数据。覆盖客户入口、售后弹窗与确认、刷新后的工单保留、测试故障隔离和数据导出。结果写入 `tests/evidence/product-browser-report.json`。

旧 `tests/browser_smoke.py` 与部分 evidence 文件保留为历史资料，其中可能引用已删除的演讲入口，不能直接当成新版浏览器验收脚本。当前验证范围见 [产品体验验收记录](tests/evidence/product-review.json)。

当前本机逻辑测试 **138/138 通过**：95 项核心逻辑、25 项流程图、12 项界面逻辑、6 项产品体验。真实 HTTP 浏览器检查覆盖售后确认受理、刷新保留、坐席处理、客户确认、历史咨询找回、草稿超时和 375px 客户页。导出内容及失败保护通过 Node 检查；浏览器实际下载落盘未确认。Python 浏览器套件未运行。

## 主要文件

`app.js` 负责页面、表单、客户入口和操作反馈；`engine.js` 保留业务状态机与规则执行；`flow-graph.js`、`flow-editor.js` 负责画布；`product-copy.js` 处理旧内置文案的兼容；`product.css` 补充客户页面布局。

`方案文档.md` 保留业务方案。`docs/产品体验调整.md` 说明页面与交互行为；原演讲脚本保留在文档目录，不在产品页面展示。
