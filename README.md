# 电商智能客服 V2

本地集成、主写及最终收敛 Agent：Codex；参与 Agent：Codex（业务审查、集成审查、回归测试）。V2 附件原始产出平台未标明；旧版视觉主题 `src/theme.css` 产出 Agent：Claude。

面向电商服务场景的本地交互原型，提供消费者服务、客服工作台、运营管理三个工作空间。默认入口加载 `src/v2/`。订单、商品、包裹、服务事项、售后申请、仓库验收与退款记录共用同一份 V2 数据。

## 运行与入口

在本目录执行：

```bash
python3 run.py --no-open
```

仅监听 `127.0.0.1:8768`，所有响应带 `Cache-Control: no-store`。省略 `--no-open` 自动打开浏览器；端口被占用时退出提示，不自动换端口。

| 入口 | 地址 |
| --- | --- |
| V2 默认入口，页面内切换三个工作空间 | [电商智能客服](http://127.0.0.1:8768/) |
| 旧电商版 | [旧电商工作空间](http://127.0.0.1:8768/ecommerce-v1.html#customer) |
| 通用 V4 | [通用 V4 工作空间](http://127.0.0.1:8768/ecommerce-v1.html?data=v4#customer) |
| 早期 V3 | [历史入口](http://127.0.0.1:8768/legacy.html) |

V2 使用页面内导航，旧版 hash 路由和 `?data=v4` 参数只适用于 `ecommerce-v1.html`。三个工作空间在同一标签页内切换角色；这不构成生产登录或权限认证。V1 的手机框演示、自动续答开关、八步 SOP 看板和部分后台菜单可通过旧入口继续使用。V2 暂未接入完整 SOP 引导面板；事项办理按钮提供对应的业务操作。

## 业务行为

- 商品属性与清洗说明有来源；本人优惠资格分别核对门槛、商品范围、有效期及叠加条件。
- 一单两件两包裹，正常在途先查询，签收未收到及停滞单独核实；混合诉求分别保留。
- 待发货订单改址与取消需预览、本人确认、提交前复查；已支付取消进入独立退款，未支付取消不生成退款。
- 退货退款、仅退款、换货、缺件补发分别收集必要信息。客户可选择本地图片；核对预览后确认受理，客服不能代替客户确认。
- 退货主线为申请、经理审核、寄回、仓库收货、验收、退款、通知、反馈。验收异常可补件及复核；未知退款查询原请求，失败或重复回执不产生第二笔退款。
- 换货和补发停在审核后的履约协调；发票、价保和维修提供结构化受理及办理协调。
- 消费者与客服的输入区保持在屏幕底部，长对话在消息区内滚动；窄屏通过服务队列、办理操作和关联信息入口访问详情。
- 两端聊天按发送时间完整展示当前会话，客户居左、AI 与人工客服居右，系统通知居中；人工回复保留发送者身份。
- 人工接管后不自动发送 AI 公开回复；转派接收前保留原责任，接收后接续同会话的未完事项。
- 场景规则、知识草稿经过验证再发布，新申请使用发布版本，既有申请保留规则快照。知识答复缺少解决反馈时不计 AI 独立解决。

详细范围见 [V2 业务需求](docs/v2/电商AI智能客服平台——业务需求文档_V2.md)及[V2 产品方案](docs/v2/电商AI智能客服平台——产品方案文档_V2.md)。

## 数据保存

V2 保存键为 `support-ecommerce-v2`（schema 6）。旧电商键 `qinghe-support-ecommerce-v1`、V4 键 `qinghe-support-v4` 及早期 V3 数据保留；V2 不读取或迁移它们。相同主机与端口可在旧入口查看原有记录，不同访问地址的数据相互独立。

现有保存值无效时阻断业务操作，不用样例覆盖；无法访问浏览器存储时明确提示窗口内运行。普通保存失败不推进内存状态。同一来源仅允许一个可编辑页面，其他页面只读；关闭编辑页后刷新接续。页面写入前比较原始保存值，拒绝较旧页面覆盖其他页的改动，写后回读确认。更高版本的有效存储事件会同步页面；同版本、删除或损坏的外部改动要求刷新核对。编辑需要浏览器原生 Web Locks；不支持该能力时保持只读，建议使用现代浏览器通过本地 HTTP 地址打开。这是本地单人演示的保护，不提供多人协同保证。

## 构建与测试

```bash
python3 build_single.py
node --test tests/*.test.cjs tests/v2-scenarios.test.js
python3 -m unittest discover -s tests -p 'test_v2_installer.py' -v
```

构建生成 `dist/智能客服.html` 与 `dist/智能客服_V2.html`，两文件内容一致且均为当前默认 V2。`python3 build_v2.py` 可单独重建 V2 文件；恢复旧入口时会拒绝生成误标版本的产物。

旧版 UI 测试明确加载 `ecommerce-v1.html`，继续验证旧模块；V2 业务与保存测试独立运行，旧测试通过不代表 V2 全功能兼容。当前实际验证及限制见 [本地 V2 验收](docs/v2/本地验收.md)；附件原始验收记录与日志保留为来源证据。

| 文件 | 用途 |
| --- | --- |
| `index.html`、`src/v2/` | V2 默认页面、业务模型、命令与样式 |
| `ecommerce-v1.html`、其余 `src/` | 旧电商及 V4 入口与原模块 |
| `run.py`、`build_single.py`、`build_v2.py` | 本地服务及构建 |
| `tests/v2-*`、`tests/test_v2_installer.py` | V2 业务、保存、页面与安装测试 |
| `docs/v2/` | V2 需求、方案和验收证据 |
| `docs/演示脚本.md`、`docs/当前方案与角色分工修改计划.md` | V1 操作脚本与历史开发设计，配合旧入口阅读 |
| `交付包/智能客服前端演示包.zip`、`MANIFEST.sha256` | 本地交付与文件校验 |

## 实现边界

问答使用关键词与确定性规则，样例均为虚构数据。未接入真实模型、RAG、订单、物流、支付、仓库、通知、服务端鉴权、多租户或跨设备同步。退款与仓库操作是本地模拟回执；换货补发未完成库存锁定、真实出库和送达，发票价保维修未提供真实执行。请勿输入真实客户资料或凭证。真实移动设备、浏览器禁止存储环境和多人并发尚未验收。
